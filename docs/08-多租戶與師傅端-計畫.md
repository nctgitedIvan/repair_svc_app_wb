# 08 · 多租戶預留與師傅端（T2 計畫）

> 建立日期：2026-10-17
> 狀態：**Phase 1／2 骨架完成**；Phase 3 之後才接真實 API。
> 本階段不改動真實雲環境，持續使用 Mock／Storage。

---

## 1. 目標

1. 讓資料模型具備 `merchantId`，為未來的多商戶（平台／加盟商）預留隔離維度。
2. 建立師傅端最小可用骨架（4 頁＋自製底部導航），與 C 端完全隔離。
3. 把「師傅只能看同商戶訂單」做成 **AccessPolicy 的 ABAC 約束**，不是散在頁面的 if。

---

## 2. 已完成（Phase 1）

### 2.1 Domain／Ports

| 位置 | 變更 |
|---|---|
| `Order` | 新增 `merchantId`（預設 `platform`），寫入 `toPersistence()`／`toSnapshot()`，`rehydrate()` 對舊資料補預設 |
| `ProductRepository`／`ServiceRepository`／`TechnicianRepository` | 契約新增 `merchantId` |
| `UserRepository` | `UserRecord` 新增 `merchantId` |
| InMemory 實作 | `Product`／`Service`／`Technician` save 時預設 `platform`；`UserRepository.seed` 預設 `platform` |
| `authenticate()`／`AuthenticateUseCase` | actor 帶出 `merchantId` |
| `toOrderDto()` | 回傳 `merchantId` |
| fake API | services／products／technician tasks 補 `merchantId: 'platform'` |

### 2.2 AccessPolicy

新增 `MerchantConstraint`：

- 只對 `technician` 生效。
- `order.merchantId !== actor.merchantId` → `MERCHANT_MISMATCH`。
- 缺少 `order` → `RESOURCE_MISSING`（fail-closed）。
- 其他角色由各自的權限矩陣控制。
- 已加入 `orders.read`／`orders.accept`／`orders.reject`／`orders.arrive`／`orders.complete`／`orders.update_status` 的 constraints。
- `InMemoryOrderQueryAdapter`／`CloudDBOrderQueryAdapter` 的 `findByIdForTechnician` 同步做商戶過濾。

## 5. 安全紅線

1. 師傅端**永遠不得**取得完整客戶手機或完整門牌；聯絡只能走 AXB 或客服三方通話。
2. `merchantId` 的比較只在 domain／AccessPolicy／Query Adapter；頁面不得自行判斷。
3. 刪除、改價、改分潤比例等高風險操作**不進師傅端**。
4. 前端全刪，後端仍必須安全：所有 action 都經 `authenticate()`＋AccessPolicy。
5. 真實雲環境（CloudDB／支付）在本階段不變更；本文件只描述骨架與計畫。
