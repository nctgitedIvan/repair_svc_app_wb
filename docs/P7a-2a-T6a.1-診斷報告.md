## 2. 收藏星星變色（需求 2）—— **好消息：圖示本來就有兩顆**

`style/iconfont.wxss` 已同時定義：

```css
.wr-star:before        { content: '\e06e'; }   /* 空心星 */
.wr-star_filled:before { content: '\e06f'; }   /* 實心星 */
```

→ **不需要新增圖示、也不需要混用 TDesign 的圖示字型**（與 tabBar 那次「不混搭」的判斷一致）。

### 2.1 ⚠️ 但你指定的做法需要調整（Q-2）

你寫的是「buy-bar 收藏按鈕加 `class="{{ isFavorited ? 'favorited' : '' }}"` + CSS 切換」，
但**那顆按鈕不在你的頁面裡** —— 它是由 `buy-bar` 依 `jumpArray` 迴圈渲染的，
頁面沒有地方掛 class。

**建議改為資料驅動**（頁面把狀態放進 `jumpArray`，元件照著畫）：

| 狀態 | `title` | `iconName` | `iconColor` |
|---|---|---|---|
| 未收藏 | 收藏 | `star` | `#BBBBBB`（灰） |
| 已收藏 | 已收藏 | **`star_filled`** | **`#FFA500`**（橙黃） |

需要的改動：`buy-bar` 的 `<t-icon>` 加 `color="{{item.iconColor}}"`（目前沒有傳色）。
這比 class 字串乾淨：**狀態只有一個來源（頁面的 `jumpArray`）**，元件不必知道「收藏」是什麼。

> 若你偏好 class 的做法，也可以做（元件多收一個 `item.class`），但那等於把
> 「收藏」這個業務概念洩漏到通用元件裡。**我建議資料驅動。**

## 3. 「頁面內容超出螢幕」診斷（需求 3）

你說的是「零件和圖片顯示都有些超出頁面」。我**看不到畫面**，所以先列出
**兩個有明確數字的機制**，再說明我需要什麼才能確認。

### 3.1 機制 A：分類頁**沒有為自訂 tabBar 留空間**（最可能）

| 事實 | 數值 |
|---|---|
| 自訂 tabBar 的實際高度 | `t-tab-bar-item` 是 `height: 80rpx` ＋ `margin: 16rpx 0` → **約 112rpx**（未計安全區） |
| 分類頁預留的底部空間 | `.cat-grid { padding: 16rpx 16rpx **32rpx** }` → **只有 32rpx** |
| 分類頁的容器 | `.wrap { height: 100vh; overflow: hidden }`；右側 `overflow: scroll` |

→ **可滾動區域的底部與 tabBar 重疊約 80rpx**，最後一列卡片的**下半部被 tabBar 蓋住**，
捲到底也看不到。這正是「內容超出頁面」的典型症狀。

> 對照組：**購物車頁有處理**（`pages/cart/index.wxss` 的 `:host { padding-bottom: 100rpx }`
> ＋ `.gap { height: 100rpx }`）；詳情頁也有（`.desc-content { padding-bottom: 120rpx }`）。
> **分類頁漏了** —— 這是 T3.6 帶進來的（我沒有把購物車那套沿用過來）。

### 3.2 機制 B：分類頁的卡片寬度是「打進共用元件內部」（次要但風險高）

| 事實 | 數值 |
|---|---|
| 共用卡片 `components/goods-card` 的固有尺寸 | `.goods-card__main { width: 342rpx }`、`.goods-card__thumb { 340rpx × 340rpx }` |
| 分類頁右側可用寬度 | 750 − 180（側邊欄）− 32（`.cat-grid` 左右 padding）＝ **538rpx** |
| 我在 T3.6 用頁面樣式覆寫成 | `__main` **264rpx**、`__thumb` **264rpx** |

覆寫靠的是 `goods-card` 的 `addGlobalClass: true`（**我無法在 CI 驗證這個機制**，
當時已標為「最可能需要微調的一處」）。若**只生效一半**：

- `__main` 生效、`__thumb` 沒生效 → 340rpx 的圖塞在 264rpx 的框裡 → **圖片向右溢出**
- 兩者都沒生效 → 一列只能放一張 342rpx 的卡（不會橫向溢出，但與你要的「兩列」不符）

**兩種症狀都符合你描述的「圖片有些超出頁面」。**

## 4. 分類頁第二級商品卡片的目前佈局（需求 4）

### 4.1 現在長什麼樣（共用卡片 `components/goods-card` 的固定結構）

```
┌──────────────────────┐
│                      │
│       圖片           │  340rpx（分類頁被覆寫成 264）
│                      │
├──────────────────────┤
│ 商品名稱（最多 2 行）  │
│ [服務]／[零件]  ←標籤  │  tags 在名稱「下方」
│ ¥80        [🛒]      │  價格靠左、購物車圖示絕對定位在右下
└──────────────────────┘
```

| 區塊 | WXML 位置（`components/goods-card/index.wxml`） |
|---|---|
| 圖片 | `.goods-card__thumb` → `<t-image>` |
| 名稱 | `.goods-card__title` |
| 標籤 | `.goods-card__tags` → `.goods-card__tag`（**在名稱的下一行**） |
| 價格 | `.goods-card__down` → `<price>` |
| 購物車圖示 | `.goods-card__add-cart`（`position: absolute; bottom: 0; right: 0`） |

**所以「價格靠左、購物車靠右」現在已經是這樣**（購物車是絕對定位在右下角）。

### 4.2 你的目標與現況的差異

| 你的描述 | 現況 | 差異 |
|---|---|---|
| 服務／零件**標籤與名稱同一行** | 標籤在名稱**下一行** | ❌ **需要改結構** |
| 下一行：價格靠左、購物車靠右 | 已經是這樣 | ✅ 大致符合 |

→ 唯一的實質差異是「**標籤與名稱同行**」。
這在共用卡片上做不到（它是 `flex-direction: column`），
必須**改共用元件**（影響 home／goods-list／coupon／promotion 四個頁面）
或**分類頁自己畫卡片**（§3.4 建議的同一條路）。
