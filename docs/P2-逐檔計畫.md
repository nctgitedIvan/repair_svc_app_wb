| action | 做法 | 回答什麼 |
|---|---|---|
| `reset` | 將 `_probe_tx/counter.value` 設為 0 | 測試前置 |

| `rmw-race` | 事務外「讀 → +1 → 寫」併發 10 次 | 無事務時是否丟更新（記錄用，不作阻斷） |

   - `reset` → `inc-atomic`（10 次併發）→ 讀值
   - `reset` → `rmw-race`（10 次併發）→ 讀值
   - `reset` → `tx-rollback` → 讀值
3. 把最終值寫回 `docs/P2-0-事務核實報告.md` §6。
4. 刪除 `probe-tx` 函數與 `_probe_tx` 集合。

### 4.5 UnitOfWork 實作要點

```
CloudDBUnitOfWork.run(fn):
  db.runTransaction(async (transaction) => {
    const tx = new CloudDBTransaction(transaction, onCommitQueue);
    const result = await fn(tx);
    return result;          // 交易提交
  })
  // 提交成功後才執行 onCommit 佇列
```

- **事務內只允許單記錄操作**（`doc().get/update/set/remove`、`add`），不得用 `where`／`aggregate`。
- 單一事務 ≤ 100 次操作、≤ 30 秒（文檔限制）；大批次改兩段式（先查 ID，再逐筆事務）。
- `onCommit` 副作用（通知）**不得**在事務內執行。
- 衝突重試：使用 `runTransaction` 的自動重試；手動 `startTransaction` 不採用（除非需要更細控制）。

## 6. CloudDB 映射（snake_case ↔ camelCase）

### 6.1 原則

- DB 一律 **snake_case**；domain／application 一律 **camelCase**。
- 金額一律整數「分」＋ `currency`；時間一律 Unix ms。
- 每個集合一個 **mapper**（純函式，放 `packages/adapters/clouddb/mappers/`）：
  `toRow(record)`／`fromRow(row)`。
- 明列映射，不用通用 `snakeCase()` 轉換 —— 巢狀快照與例外欄位太多，通用轉換容易錯。
- `updated_at` 由 adapter 在寫入時填入；`created_at` 由 Use Case 傳入（不讓 adapter 產生時間）。

### 6.2 需要特別處理的集合

| 集合 | 重點 |
|---|---|
| `orders` | 主檔＋`order_items`＋`order_status_logs` 三個集合；`orderNo` 是值物件；`amounts` 拆成 `service_fee_cents`／`material_fee_cents`／`total_cents`；`snapshot.profitSharingTerms` 巢狀 |
| `products` | `specs`／`skus` 陣列；`price_cents`；`category_id`；`images` |
| `services` | `duration_minutes`／`skill_tags` |
| `carts` | `items` 內嵌；欄位名 `sku_id` |
| `inquiries` | `product_snapshot` 巢狀；`replies` 陣列 |
| `favorites` | 複合唯一鍵 `(customer_id, product_id)` |
| `audit_logs` | `prev_hash`／`hash`／`seq`／`chain_id`；只 append |

### 6.3 OrderRepository 的讀寫

- **save(order)**：
  1. 以 `order.version` 做樂觀鎖（`where({ orderId, version: order.version - 1 })` 或事務內比對）。
  2. upsert `orders` 主檔。
  3. 新增／更新 `order_items`（用 `line_id` 或 `order_id`＋序號）。
  4. 追加新的 `order_status_logs`（只 append，不刪）。
  5. 全部在同一個 `UnitOfWork` 事務內（≤100 次操作；訂單明細數量需 < 100）。
- **findById／findByOrderNo**：讀三個集合，`Order.rehydrate()`。
- **findExpiredUnpaid／findExpiredUnassigned**：`where` 查 `orders`，再逐一載入 items/logs（注意 N+1；P2 可接受，P5 量測後優化）。

## 7. InMemory Repositories

- 每個 Port 一個 `InMemory*Repository`，行為與 CloudDB 版**一致**（含樂觀鎖、唯一鍵、軟刪除）。
- 內部存 `toPersistence()` 的純資料，讀取時 `rehydrate` —— 與真實 adapter 的行為一致。
- 提供測試輔助：`seed()`／`size()`／`rawRow()`（不進 Port 契約）。
- **不供前端使用**（見 §1.3）。
