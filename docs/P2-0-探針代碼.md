# P2-0 事務能力核實 — 探針代碼與操作手冊

> 用途：回答「微信雲開發資料庫是否支援原子讀-改-寫」，決定 `dailyRefundBudget` 的保護策略。
> **這是 P2a 的阻斷級前置。**
> 執行環境：**`repair-test`**（`_probe_tx` 是臨時集合，不要在生產建）
> 完成後整份刪除，見 §5。

---

## 1. 要回答的三個問題

| # | 問題 | 若為「是」 |
|---|---|---|
| 1 | `db.startTransaction()` 可用，且支援讀-改-寫？ | 配額保護用事務，最乾淨 |
| 2 | 無保護的讀-改-寫在併發下會**丟更新**嗎？ | 若會丟 → 絕不可用「讀→改→寫」 |
| 3 | `_.inc()` 原子遞增可靠嗎？ | 若可靠 → 可作為無事務時的退路 |

### 2.2 `cloudfunctions/probe-tx/index.js`

> **刻意不依賴 `@repair/*`** —— 這是診斷工具，不是業務代碼。
> 它必須在共享碼同步出問題時仍能獨立運作。

```js
'use strict';

/**
 * probe-tx —— 資料庫原子性探針（臨時）。
 *
 * 併發 N 次「+STEP」，最終值應為 N × STEP。
 * 小於 → 有競態，更新被覆蓋。
 */

const cloud = require('wx-server-sdk');
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV });

const db = cloud.database();
const _ = db.command;

const COLLECTION = '_probe_tx';
const DOC_ID = 'counter';
const STEP = 1000;

async function reset() {
  try {
    await db.collection(COLLECTION).doc(DOC_ID).remove();
  } catch (e) {
    // 不存在就當作已重置
  }
  await db.collection(COLLECTION).add({
    data: { _id: DOC_ID, usedCents: 0, version: 0 },
  });
  return 0;
}

async function readValue() {
  const r = await db.collection(COLLECTION).doc(DOC_ID).get();
  return r.data.usedCents;
}

/** ① 讀-改-寫，無任何保護 */
async function incReadModifyWrite() {
  const r = await db.collection(COLLECTION).doc(DOC_ID).get();
  const next = r.data.usedCents + STEP;
  await db.collection(COLLECTION).doc(DOC_ID).update({ data: { usedCents: next } });
  return next;
}

/** ② 讀-改-寫，包在事務內 */
async function incInTransaction() {
  const transaction = await db.startTransaction();
  try {
    const r = await transaction.collection(COLLECTION).doc(DOC_ID).get();
    const next = r.data.usedCents + STEP;
    await transaction
      .collection(COLLECTION)
      .doc(DOC_ID)
      .update({ data: { usedCents: next } });
    await transaction.commit();
    return next;
  } catch (err) {
    await transaction.rollback();
    throw err;
  }
}

/** ③ 原子遞增（不讀取，直接 inc） */
async function incAtomic() {
  await db
    .collection(COLLECTION)
    .doc(DOC_ID)
    .update({ data: { usedCents: _.inc(STEP) } });
  return null;
}

/** ④ 樂觀鎖：條件式更新，版本不符則失敗 */
async function incOptimistic() {
  const r = await db.collection(COLLECTION).doc(DOC_ID).get();
  const { usedCents, version } = r.data;
  const res = await db
    .collection(COLLECTION)
    .where({ _id: DOC_ID, version })
    .update({ data: { usedCents: usedCents + STEP, version: version + 1 } });
  return res.stats.updated; // 0 = 版本衝突（被別人改過）
}

const STRATEGIES = {
  rmw: incReadModifyWrite,
  tx: incInTransaction,
  atomic: incAtomic,
  optimistic: incOptimistic,
};

exports.main = async (event) => {
  const action = (event && event.action) || 'probe';
  const strategy = (event && event.strategy) || 'rmw';
  const concurrency = (event && event.concurrency) || 10;
  const startedAt = Date.now();

  try {
    if (action === 'reset') {
      const value = await reset();
      return { ok: true, action, value };
    }

    if (action === 'read') {
      return { ok: true, action, value: await readValue() };
    }

    if (action === 'inc') {
      const fn = STRATEGIES[strategy];
      if (!fn) return { ok: false, error: `未知策略：${strategy}` };
      const result = await fn();
      return { ok: true, action, strategy, result, value: await readValue() };
    }

    if (action === 'probe') {
      const fn = STRATEGIES[strategy];
      if (!fn) return { ok: false, error: `未知策略：${strategy}` };

      await reset();

      let success = 0;
      let optimisticConflict = 0;
      let firstError = null;

      const tasks = Array.from({ length: concurrency }, () =>
        fn()
          .then((r) => {
            if (strategy === 'optimistic' && r === 0) optimisticConflict += 1;
            else success += 1;
          })
          .catch((e) => {
            if (!firstError) firstError = String((e && e.errMsg) || e);
          }),
      );

      await Promise.all(tasks);
      const finalValue = await readValue();
      const expected = concurrency * STEP;

      return {
        ok: true,
        action: 'probe',
        strategy,
        concurrency,
        expected,
        actual: finalValue,
        lostUpdates: (expected - finalValue) / STEP,
        success,
        optimisticConflict,
        atomic: finalValue === expected,
        firstError,
        elapsedMs: Date.now() - startedAt,
        verdict:
          finalValue === expected
            ? 'ATOMIC'
            : `RACE_DETECTED（丟失 ${(expected - finalValue) / STEP} 次更新）`,
      };
    }

    return { ok: false, error: `未知 action：${action}` };
  } catch (err) {
    return {
      ok: false,
      action,
      strategy,
      error: String((err && err.errMsg) || err),
      stack: err && err.stack ? String(err.stack).slice(0, 500) : null,
    };
  }
};
```

## 3. 呼叫腳本

### 3.1 前置（在開發者工具 console 執行一次）

```js
// 確認探針已部署
wx.cloud.callFunction({ name: 'probe-tx', data: { action: 'reset' } })
  .then(r => console.log('reset →', r.result))
  .catch(e => console.error('部署失敗或 _probe_tx 集合不存在：', e));
```

> 若報「集合不存在」，需先在雲開發控制台建立 `_probe_tx` 集合（權限：僅管理端可讀寫）。

### 3.2 模式一：同一次呼叫內併發

```js
const run = (strategy) => wx.cloud.callFunction({
  name: 'probe-tx',
  data: { action: 'probe', strategy, concurrency: 10 },
}).then(r => console.log(strategy, '→', r.result));

run('rmw');         // ① 無保護
run('tx');          // ② 事務
run('atomic');      // ③ 原子遞增
run('optimistic');  // ④ 樂觀鎖
```

### 3.3 模式二：跨呼叫併發（10 個雲函數實例同時跑）

```js
const crossInvoke = async (strategy, n = 10) => {
  await wx.cloud.callFunction({ name: 'probe-tx', data: { action: 'reset' } });
  await Promise.all(Array.from({ length: n }, () =>
    wx.cloud.callFunction({ name: 'probe-tx', data: { action: 'inc', strategy } })
  ));
  const r = await wx.cloud.callFunction({ name: 'probe-tx', data: { action: 'read' } });
  console.log(strategy, '跨呼叫 → 最終值:', r.result.value, '（期望', n * 1000, '）');
};

crossInvoke('rmw');
crossInvoke('tx');
crossInvoke('atomic');
crossInvoke('optimistic');
```

### 3.4 序列對照組（確認探針本身正確）

```js
// 序列執行 10 次，任何策略都應該得到 10000
const sequential = async (strategy, n = 10) => {
  await wx.cloud.callFunction({ name: 'probe-tx', data: { action: 'reset' } });
  for (let i = 0; i < n; i++) {
    await wx.cloud.callFunction({ name: 'probe-tx', data: { action: 'inc', strategy } });
  }
  const r = await wx.cloud.callFunction({ name: 'probe-tx', data: { action: 'read' } });
  console.log(strategy, '序列 → 最終值:', r.result.value, '（必須是', n * 1000, '）');
};

sequential('rmw');
```

> **序列測試是必要的對照組**：若序列也拿不到 10000，代表探針本身有 bug，後面的併發結果就無意義。

## 4. 預期結果判讀表

### 4.1 同一次呼叫內併發（concurrency=10，期望 10000）

| 策略 | 結果 | 判讀 | 下一步 |
|---|---|---|---|
| `rmw` | **< 10000** | ✅ 如預期，**資料庫層級確實有競態** | 不可用讀-改-寫 |
| `rmw` | = 10000 | ⚠️ 意外。可能是同呼叫內被序列化 | **必須再用跨呼叫模式驗證** |
| `tx` | = 10000 | ✅ **支援事務** | **採策略 1（事務）** |
| `tx` | 拋錯 | `startTransaction` 不存在或 API 不同 | 往策略 2 或 3 |
| `atomic` | = 10000 | ✅ **`_.inc()` 可靠** | 可作為退路 |
| `atomic` | < 10000 | 🔴 嚴重。原子遞增不可靠 | 只能走序列化 |
| `optimistic` | `optimisticConflict > 0` 但最終 = 10000 | ✅ 樂觀鎖運作正常（衝突被偵測並放棄） | 可用，但需重試邏輯 |

### 4.2 跨呼叫併發（10 個實例，期望 10000）

**這才是真實情境**（生產環境就是多實例併發）。

| 策略 | 最終值 | 判定 |
|---|---|---|
| `rmw` | < 10000 | 🔴 **確認有競態** → 配額保護絕不可用讀-改-寫 |
| `tx` | = 10000 | ✅ 事務在跨實例下仍正確 → **採策略 1** |
| `tx` | < 10000 | 🔴 事務不保證跨實例隔離 → 需策略 3 |
| `atomic` | = 10000 | ✅ `_.inc()` 跨實例可靠 → **可採策略 2** |
| `optimistic` | = 10000（有衝突計數） | ✅ 樂觀鎖可行 → 需實作重試 |

### 4.3 三種結果對應的三種實作（回填 `docs/02` §3.0）

| 結果組合 | `CloudDBUnitOfWork` 實作 | 連帶影響 |
|---|---|---|
| **`tx` = 10000（同呼叫 + 跨呼叫）** | `db.startTransaction()` 包裹三步 | 無 |
| `tx` 不可用，但 `atomic` = 10000 | **樂觀鎖**（`version` + 條件更新）+ 原子遞增 | `cs_agents` 需加 `version` 欄位 |
| 兩者皆不可行 | **配額串行化**（獨立雲函數／心跳鎖） | **§5 雲函數拆分方案需加一支配額服務** |
