### 1.2 橫向還是縱向？

依你描述的「圖片和零件文字都超出頁面」，**指向橫向**（右側被切掉／可左右滑）。
縱向的部分已經在 T6a.1-1 修過（底部留白 160rpx），若你看到的是「底部被購買列蓋住」，
那是另一個問題，請一併在截圖裡指出。

> 「零件文字」我理解為**價格列右側的「零件」標籤**（詳情頁的型別標籤），
> 它在 `.goods-number { justify-content: space-between }` 的最右緣。

### 1.3 關鍵的算術（這是根因的來源）

```
頁面寬度            750rpx
.goods-info 的 padding  左 30rpx、右 0     ← ⚠️ 只有左邊
→ 內容盒寬度         720rpx

標題列： 600 (goods-name) + 26 (margin) + 104 (goods-tag) = 730   → 超出 10rpx
底欄：   110×2 (圖示) + 254×2 (按鈕) = 728；扣掉 footer 的 padding 32 → 可放 718  → 超出 10rpx
```

⚠️ `.goods-info` **只有左 padding、沒有右 padding** 是 TDesign 原模板的寫法
（它假設內容都是全寬的圖），而這一頁現在有大量靠右的文字 →
**任何 10rpx 的誤差都會直接貼到螢幕邊緣、看起來就是「超出」**。

## 3. 為什麼會「整頁都超出」而不只是那一列

專案裡**沒有任何 `overflow-x: hidden`**（`page` 與根節點都沒有）。
微信小程序的頁面預設允許左右滾動 → 只要**任何一個**元素超出 1rpx，
使用者就能把整頁往右拖，於是：

- 750rpx 的商品大圖會被往左推 → **看起來「圖片超出／被切」**
- 貼在右緣的「零件」標籤也跟著被推出去 → **看起來「文字超出」**

**所以症狀是「整頁」而不是「某一塊」** —— 這也是為什麼你會同時看到圖片和文字。

## 4. 建議的修法（T6a.2，**確認後才動**）

| # | 改動 | 為什麼 |
|---|---|---|
| 1 | `page { overflow-x: hidden }`（本頁 wxss） | **最後一道防線**：任何意外超出都不會讓整頁可左右滑 |
| 2 | `.goods-info` 補 `padding-right: 30rpx` | 讓內容盒左右對稱（720 → 690rpx），右緣不再貼邊 |
| 3 | `.goods-title` 改成 `.goods-name { flex: 1; min-width: 0; width: auto }`、`.goods-tag { flex-shrink: 0; margin-left: 20rpx }` | 移除 600rpx 魔術數字；長名稱會在框內換行／截斷，不再撐寬 |
| 4 | `.desc-content__text` 補 `word-break: break-word; overflow-wrap: anywhere` | 長英數不會撐出去（也是未來 `detail_html` 的前置） |
| 5 | `.spu-select .content` 補 `min-width: 0` | flex 子項的標準修法 |
| 6 | buy-bar：按鈕 **254rpx → 240rpx**（2×240 + 220 = 700 ≤ 718 ✓），並給 `.buy-buttons`／按鈕加 `flex-shrink: 0`，讓左側圖示區可收縮 | 四個元素放得下且不會被壓扁 |
| 7 | 全頁 `image { max-width: 100% }`（本頁 wxss） | 你的檢查點 1 |
| 8 | ⚠️ **`t-swiper` 的內部樣式我改不到**（TDesign 元件）；若截圖顯示**大圖本身**溢出，改為在頁面控制：`t-swiper` 外包一層 `width:100%; overflow:hidden` 的容器 | 需要先看截圖確認 |

**我建議一併做 1–7**（都是低風險的收斂），第 8 項等截圖。
