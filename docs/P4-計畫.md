## 1. 為什麼 P4 會改動 P0/P1 的既有檔案

這是**順序調整的預期結果**，不是意外：

| P0/P1 的產物 | 為何要改 |
|---|---|
| `Money.js` | 缺 `currency`（§12.B-1） |
| `Errors.js` | 缺 `SoDViolationError`、`PeriodClosedError` 等（§12.B/C） |
| `OrderRepository.js` | 對齊**真實聚合**（原為 P0 的佔位形狀） |
| `InMemoryOrderRepository.js` | 同上 |
| `ComputeProfitShareUseCase.js` | 同上；並改用 `Money` 的幣別檢查 |
| 對應測試 | 同上 |

**這正是把 P4 提前的價值**：這些改動若等到 P2 寫完 `CloudDBOrderRepository` 才做，要改的東西會多一倍。
